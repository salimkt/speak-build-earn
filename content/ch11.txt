# 11 | Tech skills that pay more | കൂടുതൽ ശമ്പളം കൊണ്ടുവരുന്ന കഴിവുകൾ
SUMMARY: ഉയർന്ന ശമ്പളമുള്ള AI, backend റോളുകളിൽ എത്താൻ ഏതൊക്കെ tech skills ആണ് ഏറ്റവും സഹായിക്കുക? ഓരോന്നും എങ്ങനെ പഠിക്കാം, ഒരു ചെറിയ project എന്ത് ചെയ്യാം, interview-ൽ അതിനെക്കുറിച്ച് എങ്ങനെ സംസാരിക്കാം... ഇതെല്ലാം നമ്മൾ ഈ അധ്യായത്തിൽ കാണും. ഒപ്പം system design ഉത്തരങ്ങൾക്കുള്ള ഇംഗ്ലീഷും.

## 11.0 Where the gap usually is | സാധാരണയായി കുറവുള്ളത് എവിടെ

കേരളത്തിൽ നിന്നുള്ള പല engineers-നും നല്ല production അനുഭവം ഉണ്ട്. പക്ഷേ ഉയർന്ന ശമ്പളമുള്ള റോളുകളുടെ കാര്യത്തിലോ? അതായത് Gulf കമ്പനികൾ, remote USD ജോലികൾ, AI product കമ്പനികൾ. അവിടെ സാധാരണയായി മൂന്ന് കാര്യങ്ങളാണ് കുറവ്.

1. ഒന്ന്, interview-ലെ ആദ്യ filter കടക്കാനുള്ള DSA-യും system design-ഉം.
2. രണ്ട്, cloud-ൽ ഒരു തെളിവ്. മിക്കപ്പോഴും അത് AWS certification ആണ്.
3. മൂന്ന്, LLM evals പോലെ ആഴമുള്ള ഒരു niche. ഒപ്പം അത് പുറത്ത് കാണിക്കുന്ന ഒരു public project-ഉം.

ഈ കഴിവുകൾ ഓരോന്നും എന്തുകൊണ്ട് പണം കൊണ്ടുവരുന്നു എന്ന് ആദ്യം മനസ്സിലാക്കൂ. പിന്നെ താഴെയുള്ള ക്രമത്തിൽ പഠിക്കുക. എല്ലാം ഒരേസമയം തുടങ്ങരുത്. ഒന്ന് പൂർത്തിയാക്കുക, അത് ഒരു project ആയി കാണിക്കുക, എന്നിട്ട് അടുത്തത്.

## 11.2 DSA for interviews | ഡാറ്റാ സ്ട്രക്ചറുകളും അൽഗോരിതങ്ങളും

### Why it pays | എന്തുകൊണ്ട്

ജോലിയിൽ നിങ്ങൾ ദിവസവും binary search എഴുതുന്നുണ്ടാവില്ല. പക്ഷേ മിക്ക നല്ല കമ്പനികളും ആദ്യം ഒരു online coding test അയക്കും. എന്തുകൊണ്ട്? ആയിരക്കണക്കിന് applications ഉള്ളപ്പോൾ, അതാണ് അവരുടെ ഏറ്റവും എളുപ്പമുള്ള filter. ഇത് കടന്നില്ലെങ്കിൽ, നിങ്ങളുടെ മികച്ച production അനുഭവം ഒരു interviewer-ഉം കേൾക്കില്ല.

### How to learn | എങ്ങനെ പഠിക്കാം

- NeetCode 150 list, topic അനുസരിച്ച്: arrays, hashing, two pointers, sliding window, stack, binary search, trees, graphs, heaps, DP basics.
- ദിവസവും 45 മിനിറ്റ്. 20 മിനിറ്റ് സ്വയം ശ്രമിക്കൂ. കിട്ടിയില്ലെങ്കിൽ solution കാണുക. എന്നിട്ട് അടുത്ത ദിവസം വീണ്ടും സ്വയം എഴുതി നോക്കുക.
- **ഉറക്കെ ഇംഗ്ലീഷിൽ ചിന്തിക്കുക.** Interview-ൽ നിശ്ശബ്ദമായി code എഴുതുന്നത് ഒരു നെഗറ്റീവ് ആണ്. ഒപ്പം, ഇത് ഒരു English practice കൂടിയാണ്!

### Small project | ചെറിയ project

ഒരു "pattern notebook" ഉണ്ടാക്കൂ. ഓരോ pattern-നും ഒരു പേജ്. എപ്പോൾ ഉപയോഗിക്കണം, ഒരു template code, മൂന്ന് ഉദാഹരണ problems. ഇത് GitHub-ൽ public ആക്കുകയും ചെയ്യാം.

### Say it in the interview | Interview-ൽ എങ്ങനെ പറയാം

EN: Let me restate the problem to make sure I understand it.
EN: My first idea is a brute force solution, which is O of n squared.
EN: We can do better with a hash map. That makes it O of n time and O of n space.
EN: Let me code it, and then test it with an empty list and with duplicates.

TIP: Optimal solution ഉടനെ കിട്ടിയില്ലേ? സാരമില്ല, brute force ആദ്യം പറയുക. Interviewer-ന് കാണേണ്ടത് നിങ്ങളുടെ ചിന്താരീതിയാണ്.

## 11.3 LLM system design | എൽഎൽഎം സിസ്റ്റം ഡിസൈൻ

### Why it pays | എന്തുകൊണ്ട്

Senior റോളുകളിൽ ഏറ്റവും ഭാരമുള്ള round ഇതാണ്. ഇവിടെ അവർ നോക്കുന്നത് ഒന്ന് മാത്രം: "ഇയാളെ ഒരു system മുഴുവനായി ഏൽപ്പിക്കാമോ?" Production-ൽ RAG, agents, model serving എന്നിവ ചെയ്തിട്ടുള്ളവർക്ക് ഇവിടെ വലിയ മുൻതൂക്കമുണ്ട്. കാരണം, അവർക്ക് യഥാർത്ഥ trade-offs അറിയാം.

### How to learn | എങ്ങനെ പഠിക്കാം

- അടിസ്ഥാനങ്ങൾക്ക് System Design Primer: caching, queues, load balancing, databases.
- AI ഭാഗത്തിന് AI Engineering എന്ന O'Reilly പുസ്തകം: RAG, evals, model selection, cost.
- ആഴ്ചയിൽ ഒരു design ഉറക്കെ പറഞ്ഞ് record ചെയ്യൂ. 11.10-ലെ drill കാണുക.

### Small project | ചെറിയ project

ഒരു ചെറിയ LLM gateway ഉണ്ടാക്കാം. ഒരു API, പിന്നിൽ രണ്ട് models. ലളിതമായ ചോദ്യങ്ങൾ ചെറിയ model-ലേക്ക്, ബുദ്ധിമുട്ടുള്ളവ വലുതിലേക്ക്. ഒരേ ചോദ്യത്തിന് cache. ഓരോ request-ന്റെയും cost, latency log ചെയ്യുക. ഒരു design round-ൽ ഇത് നിങ്ങൾക്ക് ഉദാഹരണമായി പറയാം.

### Say it in the interview | Interview-ൽ എങ്ങനെ പറയാം

EN: In a previous project, I routed simple queries to a small model and hard ones to a larger model.
EN: That cut our cost per request by about 60 percent, with no drop in answer quality on our test set.

## 11.4 LLM evals | എൽഎൽഎം ഇവാലുവേഷൻ

### Why it pays | എന്തുകൊണ്ട്

ഒരു LLM demo ഉണ്ടാക്കാൻ ഒരു ദിവസം മതി. പക്ഷേ "ഈ മാറ്റം കൊണ്ട് system മോശമായില്ല" എന്ന് തെളിയിക്കണമെങ്കിലോ? അതിന് evals വേണം. കമ്പനികളുടെ ഏറ്റവും വലിയ പേടി എന്താണ്? ഒരു prompt മാറ്റം കൊണ്ട് production-ൽ പെട്ടെന്ന് ഉത്തരങ്ങൾ മോശമാകുന്നത്. ഇത് തടയാൻ കഴിയുന്നവർ കുറവാണ്. അതുകൊണ്ട് അവർക്ക് വില കൂടുതലാണ്.

### How to learn | എങ്ങനെ പഠിക്കാം

- Golden dataset: യഥാർത്ഥ ചോദ്യങ്ങളും ശരിയായ ഉത്തരങ്ങളും, 50 മുതൽ 200 വരെ.
- LLM-as-judge: ഒരു model ഉപയോഗിച്ച് ഉത്തരങ്ങൾക്ക് score നൽകുക. ഒരു വ്യക്തമായ rubric വെച്ച്.
- RAG metrics: recall at k, faithfulness. അതായത്, ഉത്തരം sources-ൽ ഉള്ളതാണോ എന്ന്.
- CI-ൽ regression gate: score ഒരു പരിധിക്ക് താഴെ പോയാൽ, release തടയുക.
- LLM evals-നെക്കുറിച്ചുള്ള അറിയപ്പെടുന്ന blog posts-ഉം courses-ഉം വായിക്കൂ. Model providers-ന്റെ eval docs-ഉം.

### Small project | ചെറിയ project

നിങ്ങളുടെ ഏതെങ്കിലും ഒരു RAG അല്ലെങ്കിൽ chatbot repo എടുക്കുക. അതിൽ ഒരു eval harness ചേർക്കുക. 50 ചോദ്യങ്ങൾ, ഒരു judge prompt, ഒരു command കൊണ്ട് മുഴുവൻ score. README-ൽ ഒരു "before and after" table കൂടി ഇടുക: prompt മാറ്റിയപ്പോൾ score എങ്ങനെ മാറി എന്ന്.

### Say it in the interview | Interview-ൽ എങ്ങനെ പറയാം

EN: We don't ship a prompt change without running our eval set.
EN: It has 200 real questions. If faithfulness drops by more than two points, the release is blocked.

## 11.5 AWS certification | എഡബ്ല്യുഎസ് സർട്ടിഫിക്കേഷൻ

### Why it pays | എന്തുകൊണ്ട്

പല job posts-ലും "AWS experience required" എന്ന് കാണും. Recruiters പലപ്പോഴും keyword നോക്കിയാണ് CV filter ചെയ്യുന്നത്. നിങ്ങളുടെ അനുഭവം മറ്റൊരു cloud-ലോ on-prem-ലോ ആണോ? എങ്കിൽ ഒരു certification ആ വിടവ് വേഗം നികത്തും. പഠിക്കുന്ന concepts, അതായത് networking, IAM, storage, എല്ലാ cloud-ലും ഉപകാരപ്പെടും.

### How to learn | എങ്ങനെ പഠിക്കാം

- Solutions Architect Associate, അല്ലെങ്കിൽ Machine Learning Engineer Associate.
- AWS Skill Builder-ലെ free courses, official exam guide.
- Practice exams: ഓരോ തെറ്റായ ഉത്തരവും എന്തുകൊണ്ട് തെറ്റി എന്ന് എഴുതി വെക്കൂ.

### Small project | ചെറിയ project

നിങ്ങളുടെ ഒരു AI project AWS-ൽ deploy ചെയ്യുക. Container ആയി, ഒരു load balancer-ന് പിന്നിൽ, logs CloudWatch-ൽ. Infrastructure code ആയി എഴുതുക. Free tier കഴിഞ്ഞാൽ cost വരാതിരിക്കാൻ ഒരു budget alert-ഉം വെക്കുക.

### Say it in the interview | Interview-ൽ എങ്ങനെ പറയാം

EN: I'm AWS certified, and I deployed my voice agent demo on ECS behind a load balancer, with the whole setup written as code.

## 11.6 Real-time voice agents | തത്സമയ വോയ്സ് ഏജന്റുകൾ

### Why it pays | എന്തുകൊണ്ട്

Text chatbots ഇപ്പോൾ എല്ലാവരും ഉണ്ടാക്കുന്നുണ്ട്. പക്ഷേ ഫോണിൽ സ്വാഭാവികമായി സംസാരിക്കുന്ന ഒരു agent ഉണ്ടാക്കുന്നത് പ്രയാസമാണ്. എന്തുകൊണ്ട്? Latency, ഇടയ്ക്ക് കയറി സംസാരിക്കുമ്പോൾ നിർത്തുക, accents, noise. Clinics, call centers, real estate പോലുള്ളവ ഇതിന് നല്ല പണം നൽകാൻ തയ്യാറാണ്.

### How to learn | എങ്ങനെ പഠിക്കാം

- LiveKit Agents അല്ലെങ്കിൽ Pipecat docs, examples.
- Pipeline മനസ്സിലാക്കുക: ആദ്യം streaming speech-to-text, പിന്നെ LLM, പിന്നെ text-to-speech.
- Barge-in: user സംസാരിക്കാൻ തുടങ്ങിയാൽ, agent ഉടനെ നിർത്തണം.
- ലക്ഷ്യം: user നിർത്തിയത് മുതൽ agent തുടങ്ങുന്നത് വരെ, 800 milliseconds-ൽ താഴെ.

### Small project | ചെറിയ project

ഒരു clinic appointment booking agent ഉണ്ടാക്കി നോക്കൂ. ഇംഗ്ലീഷിലും മറ്റൊരു ഭാഷയിലും, ഉദാഹരണത്തിന് Arabic അല്ലെങ്കിൽ Malayalam. ഒഴിവുള്ള സമയം പരിശോധിക്കുന്ന ഒരു tool. പിന്നെ ഒരു public demo video.

### Say it in the interview | Interview-ൽ എങ്ങനെ പറയാം

EN: The hardest part was latency. I streamed every stage, so the agent starts speaking about 700 milliseconds after the user stops.

## 11.7 TypeScript and Node backend | ടൈപ്പ്സ്ക്രിപ്റ്റ്, നോഡ്

### Why it pays | എന്തുകൊണ്ട്

AI product കമ്പനികളിൽ പലപ്പോഴും രണ്ട് ഭാഗങ്ങളുണ്ടാകും. Python-ൽ model ഭാഗം, TypeScript-ൽ product ഭാഗം. രണ്ടും അറിയുന്നയാൾക്ക് ഒരു feature തുടക്കം മുതൽ അവസാനം വരെ ഏറ്റെടുക്കാം. Freelance-ലോ? Client-ന്റെ നിലവിലുള്ള web app പലപ്പോഴും Node ആയിരിക്കും.

### How to learn | എങ്ങനെ പഠിക്കാം

- TypeScript-ന്റെ types, async, error handling.
- ഒരു ചെറിയ API framework, ഒരു database library.
- MCP tool servers: AI agents-ന് ഉപയോഗിക്കാവുന്ന tools എഴുതി നോക്കുക.

### Small project | ചെറിയ project

നിങ്ങളുടെ ഒരു internal tool എടുക്കുക, ഉദാഹരണത്തിന് ഒരു ticket search. അതിനെ ഒരു MCP server ആക്കി മാറ്റുക. ഒരു AI assistant-ന് അത് ഉപയോഗിക്കാൻ കഴിയണം.

### Say it in the interview | Interview-ൽ എങ്ങനെ പറയാം

EN: I'm strongest in Python, but I'm comfortable in TypeScript. I recently built an MCP server in Node so our agents could search tickets.

### Why it pays | എന്തുകൊണ്ട്

ഒരു client-നോ hiring manager-നോ നിങ്ങളുടെ code വായിക്കാൻ സമയമില്ല. പക്ഷേ രണ്ട് മിനിറ്റ് video അവർ കാണും. നന്നായി കാണിക്കാനും ലളിതമായി വിശദീകരിക്കാനും കഴിയുന്നയാൾക്ക് കൂടുതൽ projects കിട്ടും, കൂടുതൽ വിശ്വാസവും. ഈ പുസ്തകത്തിലെ English practice മുഴുവൻ ഇവിടെ നേരിട്ട് പണമായി മാറുന്നു!

## 11.9 Forward Deployed Engineer skills | ഫോർവേഡ് ഡിപ്ലോയ്ഡ് എഞ്ചിനീയർ

Forward Deployed Engineer, ചുരുക്കത്തിൽ FDE. ആരാണിത്? Client-ന്റെ അടുത്തിരുന്ന്, ഒരു product അവരുടെ യഥാർത്ഥ പ്രശ്നത്തിന് പ്രവർത്തിപ്പിക്കുന്ന engineer. ഈ അധ്യായത്തിലെ മിക്കവാറും എല്ലാ skills-ഉം ഇവിടെ ഒരുമിച്ച് വരുന്നു: system design, evals, demo, പിന്നെ Chapter 9-ലെ എഴുത്തും Chapter 10-ലെ client സംഭാഷണങ്ങളും.

AI കമ്പനികളിൽ ഇപ്പോൾ ഏറ്റവും വേഗം വളരുന്ന, നല്ല ശമ്പളമുള്ള റോളുകളിൽ ഒന്നാണ് ഇത്. ഈ റോളിനെക്കുറിച്ച് നമ്മൾ **Chapter 12**-ൽ വിശദമായി പഠിക്കും.

## 11.10 System design English | സിസ്റ്റം ഡിസൈൻ ഇംഗ്ലീഷ്

System design round-ൽ ശരിയായ ഉത്തരം മാത്രം പോരാ. **അത് പറയുന്ന ക്രമവും** അവർ വിലയിരുത്തും. താഴെയുള്ള ആറ് steps ഒരു map പോലെ ഉപയോഗിക്കൂ. ഓരോ step-ഉം ഉറക്കെ പറയുക. അപ്പോൾ നിങ്ങൾ എവിടെയാണെന്ന് interviewer-ന് എപ്പോഴും അറിയാം.

### Step 1: Clarify | ആവശ്യങ്ങൾ ചോദിക്കുക

ഉടനെ boxes വരയ്ക്കാൻ തുടങ്ങരുത്. ആദ്യം scale, latency, data എന്നിവ ചോദിക്കുക. ഇത് ഒന്നുകൊണ്ട് മാത്രം നിങ്ങൾ ഒരു senior ആയി തോന്നും!

EN: Before I design, can I check the requirements? / How many users, what latency, / and is the data sensitive?

### Step 2: Big picture | മൊത്തം ചിത്രം

EN: At a high level, there are four parts: / ingestion, retrieval, generation and evaluation.

### Step 3: Walk the request | ഒരു request-ന്റെ യാത്ര

EN: When a user asks a question, / it first goes to the API gateway, / then to the retriever, / and then to the model.

### Step 4: Trade-offs | ഗുണദോഷങ്ങൾ

ഓരോ തീരുമാനത്തിനും ഒരു വിലയുണ്ട്. അത് സമ്മതിക്കുക. "This is the best" എന്നല്ല പറയേണ്ടത്. "I'd choose this because, and the cost is" എന്ന് പറയുക.

EN: I'd choose a managed vector database here, / because the team is small. / The cost is less control over tuning.

### Step 5: Scale and failure | വളർച്ചയും പരാജയവും

EN: If traffic grows ten times, / the bottleneck will be the GPU workers, / so I'd add a queue and autoscaling.
EN: If the main model is down, / we fall back to a smaller model / and tell the user the answer may be shorter.

### Step 6: Measure | അളക്കുക

EN: To know it works, / I'd track recall at ten, / answer faithfulness, / and 95th percentile latency.

| Step | Key phrase |
| Clarify | Before I design, can I check the requirements? |
| Big picture | At a high level, there are four parts. |
| Walk the request | When a user asks a question, it first goes to... |
| Trade-offs | I'd choose X over Y because... The cost is... |
| Scale and failure | If traffic grows ten times, the bottleneck will be... |
| Measure | To know it works, I'd track... |
